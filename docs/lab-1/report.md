# Отчёт по ЛР1 — Каркас (Compose Multiplatform)

Бабикова София, ПИН-252т. Веха 1 «Каркас», стек Compose Multiplatform.
Репозиторий: `space-launches-cmp`, ветка `feature/lab-1_frame`, PR в `develop`.

## 1. Предметная область и источник данных

Тема — каталог космических запусков: список запусков с фотографиями ракет, деталь запуска с миссией,
переходы к агентству и к стартовой площадке.

Источник на вехи 2–3 — Launch Library 2, `https://ll.thespacedevs.com/2.2.0/launch/`. Без ключа,
серверная пагинация `limit`/`offset`, 7994 записи, серверный поиск `?search=`. Ограничение источника —
15 запросов в час на IP, поэтому данные для моков снимались с зеркала `https://lldev.thespacedevs.com/2.2.0/`,
у которого лимита нет.

В этой вехе сети нет по условию задания. Список работает на моках: 22 запуска, 13 агентств, 20 площадок —
`shared/src/commonMain/kotlin/ru/omgtu/babikova/spacelaunches/data/`. Поля и типы моков повторяют форму API,
включая строковый UUID у запуска и целочисленные идентификаторы у агентства и площадки, поэтому в вехе 2
моки заменяются сетевым источником внутри папки `data`, а остальной код не меняется.

## 2. Архитектура

Три слоя, все зависимости сходятся к `domain`:

| Слой | Что лежит | Файлы |
|---|---|---|
| `domain` | модели предметной области, интерфейс репозитория, фильтр по имени | `Launch.kt`, `Agency.kt`, `Pad.kt`, `LaunchRepository.kt` |
| `data` | моки и реализация репозитория | `MockLaunches.kt`, `MockAgencies.kt`, `MockPads.kt`, `LaunchRepositoryImpl.kt` |
| `ui` | экраны, компоненты, тема, навигация, UI-модели | `ui/` |

Логика экрана живёт во ViewModel: `list/`, `detail/`, `agency/`, `pad/`. У каждой ViewModel состояние
хранится в `MutableStateFlow`, наружу отдаётся `StateFlow` только для чтения; действия пользователя
приходят одним методом `onIntent` с объектом-намерением (`LaunchListIntent`, `LaunchDetailIntent`).

Зависимости уровня приложения — репозиторий, навигатор и фабрики ViewModel — создаются в корне `App.kt`
через `remember` и передаются вниз. Фабрики обязательны: в общем коде нет рефлексии, которой Android
создаёт ViewModel без аргументов, — на iOS и в wasm её нет вовсе.

## 3. Как выполнены критерии

| Критерий | Где смотреть |
|---|---|
| Навигация — Navigation 3, маршрут объектом | `Screen.kt`: `sealed interface Screen` с `data object List` и `data class Detail(id: String)`, `Agency(id: Int)`, `Pad(id: Int)` |
| Мультиплатформенная сборка навигации | `gradle/libs.versions.toml`: `org.jetbrains.androidx.navigation3:navigation3-ui` + `androidx.navigation3:navigation3-runtime`, версия 1.1.2 |
| Возврат выглядит как возврат | `ui/navigation/AppNavDisplay.kt`: заданы все три спецификации — `transitionSpec`, `popTransitionSpec`, `predictivePopTransitionSpec` |
| Подписи в ресурсах, две локали, паритет ключей | `composeResources/values/strings.xml`, `values-en/strings.xml`, проверка `tools/check-strings.py` |
| Тема — токены `MaterialTheme` | `ui/AppTheme.kt` — единственный файл с литералами цвета; поверхности берут `MaterialTheme.colorScheme` |
| Экран рисуется из состояния | экраны принимают `state` и `onIntent`, ViewModel вниз не уходит (`AppNavDisplay.kt`) |
| Отчёт компилятора включён | `shared/build.gradle.kts`, блок `composeCompiler`; отчёт — в `shared/build/compose_compiler/` |
| Список, деталь с возвратом на позицию, две локали | `LazyColumn(items, key = { it.id })`; ViewModel списка живёт в записи бэкстека и переживает уход на деталь |

Отчёт компилятора на текущем коде: `App`, `LaunchListScreen`, `LaunchDetailScreen`, `AgencyScreen`,
`PadScreen`, `LaunchCard` — `restartable skippable`.

## 4. Принятые решения

**Цвет статуса вынесен в тему, но не зависит от неё.** Статус запуска (успех, авария, к пуску готов,
дата уточняется) несёт смысл данных, поэтому его цвет — исключение из правила «только токены». Чтобы
проверка «ни одного зашитого цвета в поверхностях» проходила по грепу, литералы всё равно объявлены
в `ui/AppTheme.kt`, а наружу отдаётся функция `launchStatusColor(statusId)`.

**Статус локализуется, данные каталога — нет.** Статус — закрытый перечень API из пяти значений, он
отображается через `Map<Int, StringResource>` в `ui/model/LaunchStatusLabels.kt`. Названия миссий,
описания и имена агентств остаются на языке источника: локализуется интерфейс, а не каталог.

**Картинки — локальные, ключ — идентификатор конфигурации ракеты.** Сети в вехе нет, поэтому 19 фотографий
лежат в `composeResources/drawable/`, а `ui/model/RocketImages.kt` сопоставляет им
`rocket.configuration.id`. Поле `imageUrl` в моках сохранено в форме API — в вехе 2 картинка будет
грузиться по нему, а файл с сопоставлением уйдёт.

**Дата форматируется разбором строки, без зависимостей.** `net` приходит строкой ISO, и
`ui/model/LaunchTime.kt` собирает из неё `дд.мм.гггг чч:мм UTC`. Библиотека даты не нужна, а код остаётся
общим для desktop, Android, iOS и web — `java.time` в `commonMain` использовать нельзя.

**ViewModel детали создаётся с ключом.** `viewModel(key = "detail-${key.id}", …)`: без ключа `viewModel()`
отдаёт один экземпляр на хост, и деталь, открытая второй раз, показала бы прошлую запись.

## 5. Сложности

**Навигация вне Android.** У `NavDisplay` значения по умолчанию для спецификаций переходов на не-Android
таргетах — заглушки, бросающие `NotImplementedError`, а UI-часть Navigation 3 от Google собрана не под все
таргеты. Решение: мультиплатформенная сборка JetBrains плюс все три спецификации заданы явно.

**Пропуск рекомпозиции и стабильность.** Отчёт компилятора показывает `LaunchListState` как
`Uncertain(List)`: `List` — интерфейс, и его стабильность выясняется в рантайме. Пропуск это не ломает,
потому что состояние приходит в экран извне и не пересоздаётся в теле функции; экраны остаются
`restartable skippable`. Если бы вниз уходила ViewModel, она выводилась бы `Unstable` и сравнивалась
по ссылке — пропуск пропал бы.

**Бесконечная высота.** Деталь, агентство и площадка — `Column` с `verticalScroll`, без вложенных ленивых
списков: скролл сообщает детям, что высота не ограничена, и вложенный `LazyColumn` уронил бы экран.
На списке наоборот — `LazyColumn` с ограниченной высотой внутри `Column`.
